# Stage 06：最小确定性评测预研计划

- 日期：2026-09-09
- 工作包：`T-0601`
- 版本目标：`0.0.4-eval-preview`
- 状态边界：预研；不解除Gate 03、Gate 04或Gate 05，也不代表Gate 06通过

## 为什么现在做

Stage 05已经有可操作的核心闭环和同机重启恢复。继续堆联网、语音或登录，会让缺陷同时扩散到更多模块。当前最小动作是先固定一组能够重复执行的验收问题，确保后续修改不会破坏登录、上传、阅读、划线、证据回答、隔离和恢复。

## 冻结范围

只建立30项确定性检查：

1. 身份与CSRF：4项。
2. 上传、四格式、阅读与幂等：8项。
3. 进度、划线与删除：6项。
4. 证据回答、SSE断点续传、Trace与模型降级：7项。
5. 跨用户隔离与持久化安全：5项。

本轮不做LLM裁判、主观回答打分、联网MCP、语音、微信登录、生产数据库压测或真实书籍兼容性扩展。真实PostgreSQL＋pgvector仍由F-03-02单独门禁，不能用本地评测替代。

## 执行方式

- `evals/stage06/cases.json`是场景与严重级别清单。
- `evals/stage06/run_eval.py`使用临时目录、确定性模型和真实HTTP契约执行，并生成JSON报告。
- 每个检查记录期望、实际、耗时和通过状态；P0与P1必须全部通过。
- 只保留一次实现自测、一次Sol有界只读审计；若发现P0/P1，只集中修复一次并定向复验。

## 完成条件

- 30项清单与运行结果一一对应，没有缺失或额外结果。
- P0通过率100%，P1通过率100%，进程退出0。
- 报告包含套件版本、环境边界、总耗时、p95、分类汇总和失败明细。
- 明确写出本评测只证明开发预览合同，不证明真实模型回答质量、pgvector性能或生产多端能力。
