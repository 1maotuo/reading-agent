# Stage 05 最小纵向切片计划

- 状态：开发预览已按有界策略收口；正式 Gate 仍未通过
- 日期：2026-09-09
- 边界：Docker 与真实 PostgreSQL/pgvector 暂时延期；Gate 03、Gate 04 和 Gate 05 均不因此自动通过

## 目标

先完成一个用户能够真实操作的产品核心闭环：

```text
登录 → 上传真实书籍文件 → 解析并发布 → 网页阅读
→ 选择原文并提问 → 检索当前书籍证据 → SSE 流式回答
→ 点击引用返回原文 → 保存阅读进度、划线和本次对话
```

本工作包只证明产品交互和模块协作可以跑通。开发适配器不得被描述为生产数据库、真实多端同步或 pgvector 性能验证。

## 本轮冻结范围

### 必须实现

1. React、TypeScript、Vite 响应式网页，包含登录、书架、上传和三栏阅读器。
2. FastAPI 提供实际可调用的上传、任务、书籍、章节、正文、进度、划线、提问和 SSE 接口。
3. PDF、EPUB、TXT、Markdown 使用同一解析入口，形成真实 Book、Chapter、Block 和 Chunk，不在应用中内置假书籍。
4. 本地开发适配器保存当前进程内的用户、书籍、进度、划线、对话和证据；文件写入项目私有开发目录。
5. 划线问题优先使用划线原文；自由问题执行受书籍范围约束的本地混合检索预览。真实 pgvector 接口保持可替换，不伪造向量性能。
6. 单 Agent Runtime 组装当前问题、阅读锚点、必要书内证据和输出约束；有 API 凭证时调用千问，无凭证时使用明确标记的本地证据解释降级。
7. 回答必须先产生经过服务端回读的 Evidence，再产生 answer delta；证据不足则明确失败或降级，不编造书中观点。
8. 核心错误在界面可见：格式不支持、解析失败、任务失败、证据不足、模型不可用和请求超时。

### 本轮不做

- PostgreSQL、pgvector、Docker 修复或真实 10k 性能试验。
- 生产级账号、微信登录、对象存储、跨进程持久化和真实多端同步。
- 联网 MCP、语音、OCR、跨书记忆、自进化发布和生产部署。
- UI 动效打磨、所有书籍版式兼容和正式移动端 App。

## 开发适配边界

- 保留 Stage 04 的 Pydantic 合同和 Scope/Evidence 门禁。
- 新增实现优先放在独立模块，通过端口接入；不把内存字典散落到前端或模型代码。
- 本地检索用于打通交互闭环，结果必须标记检索实现版本；后续替换 PostgreSQL/pgvector 时不改变前端接口。
- 开发 Cookie 仅允许 localhost 使用非 Secure 配置；生产配置必须 fail closed。

| S05-01 | 登录与会话 | 正确凭证进入书架；错误凭证不枚举账号；刷新仍保留会话 |
