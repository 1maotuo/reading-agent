# Stage 05 意图识别 V2 工作包

- 日期：2026-09-10
- 状态：开发预览完成
- Gate：本工作包不改变 Gate 05 状态

## 目标

把四个互斥路由扩展成可组合的服务端意图计划，同时保持现有 Stage 05 Runtime 兼容。解决自由文本被关键词短路、引用目标未进入意图合同、追问缺少上一轮语境，以及“是否需要外部证据”无法表达的问题。

## 固定边界

- `route`和`goals`继续作为现有 Runtime 的兼容字段。
- 新合同以`scope`、`tasks`、`targets`、`context_needs`、`external_access`和`clarification_required`表达多轴意图。
- 自由文本在模型可用时一律进入结构化语义路由；关键词只保留为可观测的无模型降级路径。
- 默认路由模型为`qwen3.7-flash`、关闭思考模式、使用严格JSON Schema并设置5秒失败上限；可通过环境变量替换。
- 选区/永久划线的标识只由服务端提供；模型输出的目标标识一律不采信。
- 路由器只说明所需上下文和外部证据，不直接选择或执行工具。
- 本工作包不接入Web/MCP、不实现新的Agent Loop、不修改记忆生命周期，也不宣称真实模型质量通过。

## 处理顺序

1. 验证用户、书籍、版本、会话与显式引用作用域。
2. 为路由器提供当前问题、上一轮意图和有界问答摘要、当前章节及显式引用元数据。
3. 语义模型返回严格JSON；服务端锁定可信引用范围、移除模型生成的目标标识并补齐必要上下文。
4. 当前章节已由服务端绑定时，“这本书/这一章”属于可确定指代；模型不得因不知道书名而要求澄清。
5. 低置信度且没有显式引用时转为澄清；模型不可用、异常或输出非法时进入带原因的降级路由。
6. IntentFrame随Answer和Trace保存，供后续上下文规划与Agent Loop消费。

## 验收重点

- 闲聊不因当前打开书籍而强制进入书内证据回答。
- “怎么理解”携带显式引用时绑定服务端目标，并让语义模型识别具体任务。
- 追问得到有界上一轮上下文和`previous_turn`目标。
- 最新外部事实表达为`external_access=required`，但本轮不冒充已执行联网工具。
- 模型不可用、异常、非法输出和低置信度均有明确、安全且可测试的状态。
- 旧V1 IntentFrame可恢复为合理的V2默认轴，不破坏本地历史。
