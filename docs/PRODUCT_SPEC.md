# AI 阅读助手产品说明

- 文档状态：设计基线
- 文档版本：`0.2`
- 日期：2026-09-10
- 产品名称：AI 阅读助手（暂名）

## 一句话定义

一个在网页中陪用户阅读书籍的 AI 助手：用户上传自己的 PDF、EPUB、TXT 或 Markdown 文件后，可以直接围绕书籍连续对话，也可把划线原文作为可选上下文；系统结合当前阅读位置、书内证据和稳定偏好帮助用户真正理解，并持续保存阅读进度、对话和记忆。

## 首批用户

第一版首先服务项目发起人本人，再扩展到几十至约一百名测试用户。核心用户是愿意读书，但在哲学、经济学、心理学、脑科学、商业和其他知识类书籍中容易因术语、复杂论证和缺少即时反馈而放弃的人。

## 真实问题

1. 难书中的单词都认识，但连成段落后不理解作者到底在论证什么。
2. 用户容易顺着作者被动阅读，不知道重点、前提和论证关系。
3. 普通通用聊天工具不知道用户读到哪里，也不能稳定绑定原书证据。
4. 用户读完后的想法、困惑和偏好散落在不同对话中，下一次需要重新解释背景。
5. 国外译本可能存在表达损失，用户希望在必要时结合原文、作者背景或外部资料验证，而不是只得到脱离证据的摘要。

## 核心价值

产品不是替用户把整本书总结掉，而是在不打断阅读的前提下，让 AI 成为随时可调用的阅读辅助层：

- 解释当前句子、段落和概念；
- 补充必要的前后文；
- 根据用户偏好换一种讲法或举例；
- 区分作者原意、AI解释和外部资料；
- 把回答绑定到原文位置；
- 保存进度、划线、讨论和明确表达的稳定偏好；
- 在证据不足时承认不足，不编造原书观点。

## 第一版核心旅程

```text
登录
→ 上传一本书
→ 后台解析并建立索引
→ 在网页中阅读正文
→ 直接对话（可选附加划线原文）
→ AI按需检索书内证据
→ 返回可定位到原文的回答
→ 保存进度、对话和必要记忆
→ 在手机或电脑继续阅读
```

## 第一版范围

### 必须包含

- 用户名或邮箱加密码登录；身份模型预留手机号和微信登录，正式公开前完成微信登录。
- PDF、EPUB、TXT、Markdown 上传与统一正文解析。
- 统一网页阅读模式；PDF保留只读原版查看入口。
- 稳定的阅读位置、划线和笔记锚点。
- 单主 Agent、书内检索、必要的用户偏好和单本书记忆。
- 关键词与向量混合检索、RRF融合和重排。
- 书内证据引用、证据不足提示和回答门禁。
- 在线多端同步。
- 后台任务、失败状态、有限重试和中断恢复。
- Trace、离线评测和人工审批的受控优化闭环。

### 后续能力

- 按住说话转文字和按需语音播放。
- 联网搜索与来源阅读 MCP。
- 手机号登录。
- 更多书籍类型与表达方式 Skill。
- 小规模公开测试和运营指标。

### 第一版明确不做

- 扫描版 PDF 的 OCR。
- 多 Agent、LangChain、LangGraph或沉重 ReAct 循环。
- 模型微调。
- 任意第三方 MCP 或任意代码执行。
- 实时全双工语音、声音克隆。
- 跨书知识图谱、多人共读、公开分享书籍。
- 复杂离线编辑同步。
- Redis、Celery、Elasticsearch、Milvus、Kubernetes。
- 未经评测自动修改线上 Prompt、Skill 或检索策略。

## 交互原则

1. 默认直接进入正文，不强迫用户先做问卷或打卡。
2. AI 是辅助层，不能遮挡或取代阅读本身。
3. 对话框始终是主入口；划线只是可附加、可移除的辅助上下文，不要求用户先划线或从固定意图按钮中选择。
4. 系统不推断用户智力或“是否理解”，只记录明确偏好和可观察的阅读状态。
5. 小说默认受防剧透策略约束；知识类书籍允许用户使用全书视角。
6. 声音可以切换，但文字风格、记忆和阅读状态不随声音变化。

## 数据与隐私原则

- 用户上传的书籍仅供本人私有阅读与检索，不建立公共书库，不跨用户共享。
- 原始文件存入私有对象存储；传输使用 HTTPS，静态存储开启服务端加密。
- 每本书、每个切片、向量、对话和记忆都绑定 `user_id`。
- 模型调用只发送当前任务所需片段和必要记忆，不发送整本书。
- 不在日志和项目账本中保存密钥、完整书籍正文或未脱敏个人信息。
- 用户删除书籍时，进入可追踪的删除流程，清理原文件、解析正文、切片、向量和相关缓存。

## 第一版成功定义

只有以下纵向闭环可以被真实运行和复核，第一版才算成立：

1. 用户能够上传受支持的书籍并看到可读正文。
2. 阅读位置和划线在刷新及不同屏幕宽度下能够恢复。
3. 用户直接提出书内问题或附加划线提问后，回答包含能够返回原文的证据；轻量闲聊和澄清不伪装成书内结论，也不强制制造引用。
4. 证据不足、工具失败或解析失败时，系统不会伪造成功结果。
5. 同一账号在手机与电脑看到一致的书籍、进度和对话。
6. 关键链路有测试、Trace和可复核的验收记录。
